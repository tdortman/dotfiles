# Simplified Technical English

Use ASD-STE100 Simplified Technical English for all user-facing prose.

Apply this requirement to:

- Answers and explanations.
- Plans and progress reports.
- Documentation.
- Code comments and docstrings.
- Commit and pull-request text.

Follow these rules:

1. Use one idea in each sentence.
2. Use the active voice when the actor is known.
3. Use the simple present tense when possible.
4. Put one instruction in each sentence.
5. Put a condition before the action that depends on it.
6. Keep instruction sentences to 20 words or fewer when possible.
7. Keep descriptive sentences to 25 words or fewer when possible.
8. Use no more than six sentences in one paragraph.
9. Use one term for one concept. Do not use synonyms for variety.
10. Use words with one meaning in the applicable context.
11. Use short and familiar words when they preserve the technical meaning.
12. Remove words that do not change the meaning.
13. Use "must" for requirements.
14. Use "may" for permission.
15. Use "can" for capability.
16. Use "should" for recommendations.
17. Identify the object of relative terms such as "current", "previous",
    "latest", and "next".
18. Do not use vague judgments such as "easy", "simple", "clean", "safe",
    "robust", or "obvious". State the applicable measurable condition.
19. Preserve commands, code, identifiers, paths, API names, quoted text,
    and necessary technical terms exactly.
20. Before sending prose, revise it silently to comply with these rules.

Correctness has priority over sentence length. Do not remove necessary
technical information to satisfy a writing rule.

Do not claim that text fully complies with ASD-STE100 unless a suitable
ASD-STE100 checker validates it.
